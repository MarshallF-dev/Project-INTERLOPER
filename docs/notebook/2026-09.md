12:45 PM: The next step of this project is to convert my sky coords as text into numbers. This is because text cannot be subracted, averaged, or plotted.
    Every observation line "holds" three main things that need to be converted into numbers. These things are: 1. the right asension (east-west sky position), 2. the declination (North-South sky position), 3. the date and time.

    1. East-west position --> Degrees
        The Right Asension is measured on a 24 hour clock, instead of 360 degrees. This means that each hour is equal to 15 degrees. That is the whole "trick".

        The following code was written into itf.py, as a function to be called:
        def ra_to_degrees(ra_text): #starts a function, ra_text is whatever the function gets "handed"
            parts = ra_text.split() #.split() chops text wherever there are spaces, and gives bac a list. Ex. "12 34 56.78" --> ["12", "34", "56.78"]
            hours = float(parts[0]) #parts[0] is the first item in parts. float() turns this text into a decimal number. Hours is now equal to 12, not "12"
            minutes = float(parts[1])
            seconds = float(parts[2])
            total_hours = hours + minutes / 60 + seconds / 3600 #60 minutes in an hour, 3600 seconds in an hour. This puts everything into a decimal number of hours
            return total_hours * 15 #returns the final value back as degrees.
    
    2. North-South position --> Degrees
        The Declination is a similar idea to the Right Asension, but still different. For this, it is also important to remember that the minus sign (if there) applies to the entire "phrase", so I need to apply it to the end, to ensure that it does not flip an object to the full wrong part of the sky.

        The following code was written into itf.py, as a function to be called:
        def dec_to_degrees(dec_text):
            text = dec_text.strip() #.strip() removes black space from both ends. This matters because fixed-length files (like the itf file) are "padded" with spaces
            if text.startswith("-"): #the purpose of this if else statement is to check if there is a minus at the front. If there is, then we can multiply it by this at the end, and everything will work out.
                sign = -1
            else: 
                sign = 1

            text = text.lstrip("+-") #.lstrip("") removes the listed characters only from the left end. This takes away the sign from the text, "protecting" the arithmatic
            parts = text.split()

            degrees = float(parts[0])
            arcmin = float(parts[1])
            arcsec = float(parts[2])

            total = degrees + arcmin / 60 + arcsec / 3600 #an arcminute is 1/60 of a degree, an arcsecond is 1/3600
            return sign * total #the sign goes on last, so we just apply it to everything here.

    3. The date and time --> one number
        as is, dates look like "2025 05 08.34567". The decimal on the day is the time of day. for example, .5 would be noon, .25 would be 6AM. I want to turn that into a single running count of days, so subracting two of them gives me the time between them. Astronomers use MJD, or Modified Julian Date, which is essentially a "day counter" that's been ticking since 1898. Today is somewhere around 61,290.

        The following code was written into itf.py, as a function to be called:
            from astropy.time import Time
            def date_to_mjd(date_text):
                parts = date_text.split()
                year = int(parts[0]) #we use int here instead of float, because it makes a whole number. This is because years and months are always whole.
                month = int(parts[1])
                day_with_fraction = float(parts[2])

                day_whole = int(day_with_fraction) #cutting a decimal into a whole number throws away everything after the decimal point. Ex. 3.141592653 --> 3
                day_fraction = day_with_fraction - day_whole #isolates just the time of day part

                midnight = Time(f"{year:04d}-{month:02d}-{day_whole:02d}", format="iso", scale="utc") #builds text like "2026-05-08". the ":02" pads with a zero up to two digits, so 5 --> 05, what the tool expects. Scale = "utc" says which clock I mean. This means universial coordinated time.
                return midnight.mjd + day_fraction # .mjd gives the day count at midnight, adding the fraction moves me to the exact moment. Ex. date_to_mjd("2025 05 08.34567") should give 60803.34567
    
    4. I then created yet another function that ties them all together
        The following code was written into itf.py, as a function to be called:
            def to_numeric(row):
                row["ra_str"] = ra_to_degrees(row["ra_str"])
                row["dec_deg"] = dec_to_degrees(row["dec_str"])

### What the ITF has and hasn't already linked

Claude here helped clarify a confusion I had. observations within a tracklet are already grouped. the mpc did that, and each tracklet has its own designation. but, what I am doing here is linking the tracklets to each other, so that I can fit an orbit.

The objects here cannot simply be identified currently. A single tracklet only ever spans a few hours, because as the time between observations increases, the accuracy of any fit orbit massively declines (a single tracklet could change direction in our sky, and our observations could completly skip over that). Put simply, an arc that short is consistent with a huge range of orbits, bound and bundound. we can't recover eccentricity from it, and that's what i'm looking for. to determine an orbit, I need arcs from nights, days, or even weeks apart, which means I need to join tracklets, which starts with working out which ones belong together.

This is what the apparent rate is needed for. It lets me predict where a tracket object should be on later nights, so I compare gainst a handful of canidates instead of every single tracklet in the ifle, which would take a very long tine.

Additionally, if one designation was always one tracklet, then tnoa002 (the object with the largest number of designations in the ITF file) wouldn't have 283 observations. This either means that some designations bundle multiple different tracklets, or that a survey reused labels.
